# Архитектурное решение для управления учётными данными BionicPRO

## Реализованные изменения в диаграмме C4

### Новые компоненты

1. **Identity Gateway (Container)**
   - Технология: Spring Boot + Spring Security OAuth2
   - Роль: Центральная точка управления аутентификацией
   - Функции: Маршрутизация к региональным IdP, выпуск внутренних токенов

2. **Token Management Service (Container)**
   - Технология: Redis + JWT
   - Роль: Безопасное управление токенами
   - Функции: Обмен IdP токенов на внутренние JWT, управление сессиями

3. **User Registry (Container)**
   - Технология: PostgreSQL
   - Роль: Локальное хранение связей пользователей с региональными IdP
   - Функции: Хранение ID пользователей, связей с внешними IdP, статуса

### Региональные удостоверяющие службы (External Systems)

4. **IdP Russia (ЕСИА)**
   - Внешний удостоверяющий центр для Российской Федерации

5. **IdP EU**
   - Внешний удостоверяющий центр для Европейского Союза

6. **IdP US**
   - Внешний удостоверяющий центр для США

## Схема безопасного обмена токенами

### Authentication Flow:
1. **Мобильное приложение → Identity Gateway**: Запрос аутентификации + выбор региона
2. **Identity Gateway → Regional IdP**: OAuth2 redirect на аутентификацию
3. **Regional IdP → Identity Gateway**: Authorization code
4. **Identity Gateway → Token Management Service**: Обмен authorization code на внутренние токены
5. **Token Management Service → Identity Gateway**: Внутренние JWT токены
6. **Identity Gateway → Мобильное приложение**: **ТОЛЬКО внутренние JWT (НЕ IdP токены)**

### Token Validation Flow:
1. **Мобильное приложение → Identity Gateway**: Запрос аутентификации
2. **Identity Gateway → API**: Token validation
3. **API**: Обработка запроса с валидированными токенами

## Архитектурные принципы

### Безопасность токенов
- IdP токены **НЕ передаются** фронтенду
- Используются только внутренние JWT токены
- Token Management Service изолирует внешние токены

### Локальное хранение данных
- User Registry хранит локальные связи пользователей
- Персональные данные остаются в стране регистрации
- Соответствие требованиям локализации данных

### Мультистрановая поддержка
- Identity Gateway поддерживает маршрутизацию к различным региональным IdP
- Единый интерфейс для всех регионов
- Возможность добавления новых региональных служб

## Соответствие требованиям

✅ **Требование 1**: Унификация доступа через внешний источник в стране представительства с сохранением локального хранения данных
- Реализовано через Identity Gateway с поддержкой региональных IdP
- User Registry обеспечивает локальное хранение

✅ **Требование 2**: Безопасная схема токенов без передачи IdP токенов фронтенду
- Token Management Service обменивает IdP токены на внутренние JWT
- Мобильное приложение получает только внутренние токены

✅ **Требование 3**: Мультистрановая поддержка различных внешних удостоверяющих служб
- Поддержка IdP Russia (ЕСИА), IdP EU, IdP US
- Архитектура позволяет добавлять новые региональные IdP

## Изменения в диаграмме

### Удаленные связи:
- Прямая связь "Мобильное приложение → API" (заменена на маршрутизацию через Identity Gateway)

### Добавленные связи:
- Мобильное приложение → Identity Gateway: "Запрос аутентификации"
- Identity Gateway → API: "Token validation"
- Identity Gateway ↔ Token Management Service: "Token exchange"
- Identity Gateway → User Registry: "User lookup"
- Identity Gateway → Regional IdP (RU/EU/US): "OAuth2 redirect"
- Regional IdP → Identity Gateway: "Authorization code"

Архитектурное решение обеспечивает безопасное управление учётными данными с поддержкой региональных требований и централизованной аутентификации.
